# Slack連携の開通

## 目的

出席確認の知らせをスマートフォンで受け取るには、Slack の Incoming Webhook が要る。従来はその URL を利用者が自分で作って貼っていた。Slack のサイトでアプリを作り、Incoming Webhooks を有効にし、チャンネルを選び、URL をコピーして拡張機能へ戻る、という手順である。途中で1つでも間違えると、どこで間違えたのかが分からない。

ここでやることは、**入力を Client ID と Client Secret の2つに減らし、それ以外を自動にする** ことである。チャンネルの選択・送り先の取得・権限の追加・「Slackへ送る」の有効化・到達確認のテスト送信は、拡張機能が続けて行う。

## どのワークスペースに送るか

最初に決めるのはここで、つまずくのもここである。**学校のワークスペースは、管理者の承認がないとアプリを追加できない設定になっていることが多い。** その場合、あとの許可画面が申請フォームに変わり、承認されるまで連携できない。

すぐ使いたいなら、**自分専用の無料ワークスペースを作るのが確実**である。1人だけのワークスペースでよく、スマートフォンの Slack アプリから同じアカウントでそこに入っておけば、通知はそちらへ届く。学校のワークスペースと掛け持ちしても構わない。連携のダイアログの手順1に「自分専用のワークスペースを作る」ボタンを置いてある。

なお、Slack には画面が2種類ある。**チャンネルが並ぶいつもの画面（`app.slack.com`）と、アプリを作る開発者向けの画面（`api.slack.com`）は別物** で、ログインすると前者へ飛ばされることがある。その場合はもう一度「Slackアプリの作成画面を開く」を押せば、開発者向けの画面に入れる。

## 画面の構成

ログインを伴う作業は、ほかの設定と地続きにすると何をしている最中なのか分かりにくい。そのため連携は独立したダイアログ「サービス連携」に切り出してある。入口は2つで、サイドバーの「サービス連携」と、「出席確認の見張り」→「Slack連携」に置いた状態表示の横のボタンである。見張りの画面に残るのは「どこへ送るか」「連携する／管理する」の1行だけで、手順や入力欄は連携のダイアログ側にある。

このダイアログは、サービスを1件ずつのカードとして並べる作りにしてある。実際に Discord を2件目として足しており（[`docs/discord-link.md`](discord-link.md)）、手順の中身が違っても同じ枠に収まる。`dashboard.js` の `connectionServices()` に `{ id, name, summary, linked, state, body }` を1件足せば、一覧・状態表示・本文がそろう。進行状況の表示 (`.connection-progress`) もカードごとに分かれているため、サービスが増えても混ざらない。

## 利用者の手順

ダッシュボードのサイドバー「サービス連携」（または「出席確認の見張り」→「Slack連携」→「連携をはじめる」）を開くと、4つの手順が並ぶ。

1. **どのワークスペースに送るかを決める。** 上記のとおり。学校のワークスペースをそのまま使う場合は、この手順は不要である。
2. **「Slackアプリの作成画面を開く」を押す。** Slack の作成画面が、この拡張機能用のマニフェスト（必要な権限と戻り先URL）を入れた状態で開く。Slack 側では次のように進む。
   1. ログインを求められたら、通知を受け取りたいワークスペースのアカウントでログインする。別のワークスペースに入ってしまった場合は「Sign in to another workspace」で入り直せる。
   2. いつものチャンネル画面へ飛ばされたら、もう一度このボタンを押す。
   3. 「Create an app」が入力済みで開くので、*Pick a workspace to develop your app in* で送り先のワークスペースを選び、**Next** →（設定内容の確認）→ **Create** を押す。
   4. 作成できると、そのアプリの「Basic Information」の画面に移る。次の手順で使うのはこの画面である。
   - 事前入力の画面が開かない場合は「設定内容(JSON)をコピー」を押し、Slack の Your Apps → Create New App → *From an app manifest* に貼れば同じ状態になる。
3. **Client ID と Client Secret を貼る。** 「Basic Information」を下にたどった「App Credentials」の中にある2つである。Client Secret は初め隠れているので **Show** を押す。Signing Secret や Verification Token ではない。作成後にタブを閉じてしまった場合は「作ったアプリの一覧を開く」から戻れる。
4. **「Slackと連携する」を押す。** Slack の許可画面（*Where should ... post?*）が開くので、知らせを受け取るチャンネルを選んで **Allow** を押す。

4を押したあと、拡張機能は次を続けて行う。途中で失敗した場合は、その理由を日本語で1行表示して止まる。

- `https://slack.com/*` と `https://hooks.slack.com/*` の任意ホスト権限を、1回のダイアログでまとめて要求する。
- `chrome.identity.launchWebAuthFlow` で Slack の許可画面を開き、戻り先から認可コードを受け取る。
- `oauth.v2.access` でコードを送り先（Incoming Webhook の URL）に交換する。
- 送り先・チャンネル名・ワークスペース名を保存し、「Slackへ送る」を有効にする。
- そのチャンネルへテストの1通を送り、実際に届いたかどうかを表示する。

## なぜ Client ID と Client Secret を利用者が用意するのか

Slack の OAuth では、コードを送り先に交換する時に Client Secret が要る。開発者側の値を拡張機能へ同梱すれば入力はゼロになるが、拡張機能の中身は誰でも読めるため、配布した時点で秘密ではなくなる。ウェブストアでの公開も視野に入れているので、この方式は採らない。

そのかわり、**Client Secret は端末にも保存しない**。連携の1回のやり取りに使うだけで、成功した時点で入力欄ごと消す。連携し直す時は Slack のアプリ画面から貼り直す。Client ID は秘密ではないため、次回の入力を1つ減らす目的で保存する。

## 求める権限

| 種類 | 値 | 用途 |
| --- | --- | --- |
| Slack の scope | `incoming-webhook` のみ | 選んだ1つのチャンネルへ投稿する。メッセージやメンバーの読み取りは求めない。 |
| 任意ホスト権限 | `https://slack.com/*` | 認可コードを送り先に交換する時だけ使う。 |
| 任意ホスト権限 | `https://hooks.slack.com/*` | 出席確認を検知した時に投稿する。 |
| 権限 | `identity` | 許可画面を開き、戻り先を受け取る。利用者の Google アカウントには触れない。 |

戻り先URLは `https://<拡張機能ID>.chromiumapp.org/` の形で、拡張機能IDから決まる。`manifest.json` に `key` を固定してあるため、開発中に読み込んだ場合もウェブストア版も同じIDになり、Slack アプリ側の登録をやり直す必要はない。

## 保存するもの、しないもの

保存するのは `chrome.storage.local` の設定の中だけで、外部には送らない。

| | 保存する |
| --- | --- |
| Incoming Webhook の URL | する（送信に必要なため） |
| チャンネル名・ワークスペース名・連携日時 | する（画面表示のため） |
| ボットトークン | する（解除時に Slack 側の許可を取り消すため） |
| Client ID | する（連携し直す時の再入力を減らすため） |
| **Client Secret** | **しない** |

送り先の URL は、それを知っている相手が同じチャンネルへ書き込めるという意味で秘密にあたる。そのため画面には先頭だけを表示し、以降は伏せる。「記録をコピー」で書き出す内容からも、送り先とトークンは除く。

## 解除

「連携を解除」を押すと、次を行う。

- 保存したトークンで `auth.revoke` を呼び、Slack 側の許可を取り消す。取り消せなかった場合も、端末側の記録は必ず消す。
- 送り先・チャンネル名・トークンを消し、「Slackへ送る」を無効にする。
- `https://slack.com/*` と `https://hooks.slack.com/*` の任意ホスト権限を返す。

## 送る内容

出席確認の受付を検知した時に送るのは、科目名・時限・検知時刻・科目ページのリンクだけである。成績、課題、出欠数、氏名、学籍番号は送らない。送信は `background.js` の `postAttendanceToSlack` が行い、宛先が `https://hooks.slack.com/` で始まることと、ホスト権限があることを毎回確かめてから投稿する。

## うまくいかない時

| 表示 | 原因 |
| --- | --- |
| Client ID が違います | Basic Information の Client ID を貼り直す。Signing Secret や App ID ではない。 |
| Slack アプリに登録した戻り先が違います | Slack アプリの *OAuth & Permissions* → *Redirect URLs* に、画面に表示されている戻り先URLをそのまま登録して保存する。 |
| 許可の合図が期限切れです | 認可コードには有効期限がある。もう一度「Slackと連携する」から始める。 |
| 連携しましたが、テスト送信は届きませんでした | 送り先は取れたが投稿できていない。Slack 側でアプリやチャンネルが消えていないかを確かめ、解除してからつなぎ直す。 |

Slack 側の画面で迷った場合は、次を確かめる。

| 状況 | どうするか |
| --- | --- |
| ログインしたら、いつものチャンネル画面に飛ばされた | 「Slackアプリの作成画面を開く」をもう一度押す。開発者向けの画面は `api.slack.com` 側にある。 |
| 選びたいワークスペースが一覧に出てこない | そのワークスペースにログインできていない。「Sign in to another workspace」から入り直す。 |
| 許可画面が承認の申請フォームになる | そのワークスペースが管理者の承認を必須にしている。承認を待つか、自分専用のワークスペースを作ってやり直す。 |
| Client Secret が見つからない | 「Basic Information」→「App Credentials」の中にある。「OAuth &amp; Permissions」の画面ではない。 |

## 以前の設定からの引き継ぎ

すでに Webhook URL を貼って使っている場合、その値はそのまま連携情報として読み直され、これまでどおり動く。画面には連携済みとして表示され、チャンネル名だけが「選んだチャンネル」となる（手貼りの URL からはチャンネル名が分からないため）。新しく手で貼りたい場合のために、「すでに Incoming Webhook のURLを持っている場合」の欄も残してある。

## 未検証の項目

- Enterprise Grid（複数ワークスペースの組織）で、`org_deploy_enabled: false` のまま意図どおり1ワークスペースに入るか。
- 学校のワークスペースがアプリのインストールに管理者承認を要求する設定になっている場合、許可画面が申請フォームに変わる。その場合は承認されるまで連携できない。
- `https://api.slack.com/apps?new_app=1&manifest_json=...` による事前入力は Slack 側の画面仕様に依存する。仕様が変わった場合に備えて、JSON をコピーして貼る手段を併記している。
