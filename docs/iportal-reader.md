# iPORTALの記事リーダー

スタログ上部の「iポータルへ」の左にある「未読記事」から、その場で簡易パネルを開く。ログイン済みChromeのセッションを利用し、iPORTALタブを開かずに取得する。追加権限・ライブラリは不要。記事は画面内メモリにだけ置き、閉じると破棄する。

## ブラウザ調査（2026-09-29）

ログイン済みの `/portal/index.php` と、同ページのDOMに含まれるサイト自身のスクリプトで以下を確認した。

- 一覧取得：GET `/portal/api/portalApi.php?type=infolistJ`。`result === 'success'` の `records` を使う。
- 未読判定：`!info.viewDateTime && info.pastinfo == '0'`。
- 本文：一覧の `infoDescription`。タイトルは `infoTitle` と `infoTitle2`。
- クリック処理 `SelInfo` は本文を表示し、GET `api/portalApi.php?type=infoviewupdate&infoCode=<ID>` を送る。
- 添付：`zfileDownload.php?ph=<eventCode>&fn=<attachedFile1/2>`。
- 調査時の21記事に未読印はなかった。未読→既読の実データでの遷移は未検証。
- ブラウザ連携でのAPI URL直接表示は `ERR_BLOCKED_BY_CLIENT`、Chrome拡張管理画面は操作対象外。生のJSON応答と実拡張からの通信は未確認。確認できたサイトの処理に基づいて実装し、成功を仮定しない。

## 実装

簡易パネルではスタログと同じオリジンからfetchし、拡張ページでは既存のhost permissionでfetchする。両方で `iportal-api.js` と `iportal.js` の取得・描画・既読処理を共有する。Cookie・トークンを直接読み出したり保存したりしない。一覧取得に更新処理は含めず、利用者が未読記事を選んだ時だけ既読APIを呼ぶ。更新後は一覧を再取得し、対象記事の未読フラグが消えたことを確認してから画面に反映する。失敗時は本文と未読状態を残して再試行できる。パネルは×・Escape・背景クリックで閉じ、再び開くと一覧を取得し直す。

HTMLを挿入せずtextContentで表示し、本文のHTTP(S) URLだけリンク化する。自動一括既読、常時ポーリング、本文の永続保存は実装しない。サーバーが対象ユーザーへ返す記事だけを扱う。
