# ダッシュボードカード追加ガイド

このメモは、今後カスタムページへ新しいカードを追加するときの判断基準と実装契約をまとめたものです。カスタムページは12列・固定行高のグリッドで、利用者は登録済みの「小・中・大」だけを選べます。カードは `x`・`y` 座標を持ち、途中に空行・空列があっても自動的には詰めません。

## 最初に判断すること

新機能をカードにする前に、次を確認します。

- 一目で状況を把握したり、次の操作へ進むための要約か。
- データ件数が増えても、サイズごとの表示件数制限で収められるか。
- 210pxまたは434pxの固定高で、主要情報と操作が欠けないか。
- 同じページに一つだけ置けば目的を満たすか。
- 課題一覧や科目一覧のような、ページ全体で検索・比較・大量操作する機能ではないか。

最後の項目に該当する場合は、カード本体ではなく「件数や上位項目を示して専用ページへ誘導するカード」にします。利用者ごとに件数が変わるレコードを、個別の配置カードとして登録しません。

## サイズ契約

サイズは `dashboard-layout.js` の `SIZE_SPECS` が正です。

| サイズ | 占有範囲 | 想定用途 |
|---|---:|---|
| `small` | 横4列 × 縦1行 | 主要数値、短い状態、次の1件 |
| `medium` | 横6列 × 縦1行 | 3指標、上位3件、簡単なグラフ |
| `large` | 横12列 × 縦2行 | 一覧、詳細内訳、入力を伴うツール |

カードごとに、内容が成立するサイズだけを `allowedSizes` へ登録します。空間が足りないサイズを形式的に許可しないでください。`defaultSize` は必ず `allowedSizes` に含めます。

編集時はカード上部に42pxの操作領域が追加されます。通常表示だけでなく、編集表示でも主要内容が判別できることを確認します。

## 登録形式

カードは `dashboard.js` の `cardDefinitions()` に登録します。

```js
{
  id: "stable-card-id",
  icon: "brief",
  name: "利用者に見せる名前",
  description: "カード選択画面で用途が分かる説明。",
  allowedSizes: ["small", "medium"],
  defaultSize: "medium",
  tone: "tint-brand",
  render: renderStableCard
}
```

- `id` は保存データに残る公開識別子です。リリース後に変更しません。
- `icon` は `dashboard-icons.js` に登録されたIDです。カード選択画面と左ナビで同じ表現を再利用します。
- `name` と `description` は専門用語を避け、データの範囲を明示します。
- `tone` は任意です。既存の色クラスを優先し、意味のない装飾色を増やしません。
- `render(size)` はサイズに対応するHTML文字列を返します。
- 取得データは必ず `esc()` を通してHTMLへ埋め込みます。
- カード独自の保存キーを増やさず、必要な状態は既存の画面状態または設定モデルへまとめます。

新しいカードは既存のカスタムページへ自動追加されません。登録後にカード選択画面へ現れ、利用者が明示的に追加します。

配置データは `{ cardId, size, x, y }` です。`x` は左端を1とする列、`y` は上端を1とする行です。追加時は `findOpenPosition()` で空き位置を決め、ドラッグ後は利用者が指定した座標をそのまま保存します。他カードとの重なりは許可しませんが、カード間の空白は維持します。

## サイズ別表示の決め方

同じHTMLを縮小して押し込むのではなく、サイズごとに情報密度を変えます。

- 小：結論となる数値または1件だけを表示する。
- 中：判断に必要な内訳、または上位3件程度を表示する。
- 大：一覧や操作を表示する。ただし内部スクロールは一覧領域だけに限定する。
- 情報がない場合の空表示を必ず用意する。
- 長い科目名や課題名は省略表示し、カード高を変化させない。

## 操作とアクセシビリティ

- カード内のボタンは編集用ドラッグ操作と競合しないよう、明確なクリック領域を持たせます。
- 同一ページに同じDOM `id` が複数発生しないことを確認します。
- アイコンだけの操作には `aria-label` を付けます。
- 色だけで状態を表さず、数値または文言を併記します。
- キーボードフォーカスがカードのクリッピングで見えなくならないようにします。

## 追加時の確認項目

1. 安定したカードIDを決めたか。
2. 用途に合う登録済みアイコンを選んだか。必要なら共通カタログへラベル付きで追加したか。
3. 必要なデータが未取得の場合も描画できるか。
4. 許可した全サイズで内容が固定高に収まるか。
5. 編集状態でもカードの識別とサイズ操作ができるか。
6. カード選択画面の説明だけで用途が分かるか。
7. 設定の正規化で、不正サイズが `defaultSize` に戻るか。
8. 空行・空列を含む `x`・`y` が、ページの再読み込み、JSON書き出し・読み込み後も保たれるか。
9. `tests/dashboard-icons-smoke.cjs`、`tests/dashboard-layout-smoke.cjs` とダッシュボードの回帰テストを通したか。

カードを廃止すると、正規化時に既存ページから安全に除外されます。IDを別用途へ再利用してはいけません。
