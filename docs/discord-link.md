# Discord連携の開通

## 目的

出席確認の知らせを、Slack と同じ内容で Discord のチャンネルへも送れるようにする。Slack と Discord は排他ではなく、両方を有効にすれば両方へ届く。

Discord は Webhook だけで完結する。アプリの作成も OAuth も要らず、チャンネル設定で作った Webhook の URL を1つ貼れば済むため、[Slack連携](slack-link.md) より手順が短い。そのかわり **その URL 自体が投稿の鍵** になるので、扱いは Slack の Incoming Webhook と同じである。

## 利用者の手順

ダッシュボードのサイドバー「サービス連携」→ Discord のカードに、3つの手順が並ぶ。

1. **通知を受け取るチャンネルを決める。** 自分だけのサーバーを作ってそこへ送るのが手軽である（Discord の左端の「＋」→「オリジナルの作成」）。ほかの人のサーバーでは、ウェブフックを作るのに「ウェブフックの管理」権限が要る。
2. **ウェブフックを作って URL をコピーする。** チャンネル名の横の歯車（チャンネルの編集）→「連携サービス」→「ウェブフックを作成」→ 名前を決めて「ウェブフックURLをコピー」。サーバー設定 →「連携サービス」→「ウェブフック」からも作れる。
3. **URL を貼って「Discordと連携する」を押す。**

3を押したあと、拡張機能は次を続けて行う。失敗した場合は理由を日本語で1行表示して止まり、何も保存しない。

- `https://discord.com/*` の任意ホスト権限を要求する。
- 貼られた URL 自身へ問い合わせ（`GET`）、その Webhook が生きていることと、名前・チャンネルIDを確かめる。
- 送り先とウェブフック名を保存し、「Discordへ送る」を有効にする。
- そのチャンネルへテストの1通を送り、実際に届いたかどうかを表示する。

## 貼られた URL の扱い

Discord のクライアントによって、コピーされる URL のホストが変わる（`canary.discord.com`、`ptb.discord.com`、旧 `discordapp.com`）。また API の版が入る場合もある（`/api/v10/webhooks/...`）。これらはすべて `https://discord.com/api/webhooks/<id>/<token>` に正規化して保存する。保存する形が1つに定まるため、任意ホスト権限も `https://discord.com/*` の1つで済む。

形が違う URL（チャンネルのリンク、Slack の Webhook、似た名前のホスト）は、通信する前に弾く。

## 保存するもの

`chrome.storage.local` の設定の中だけに保存し、外部には送らない。

| | 保存する |
| --- | --- |
| ウェブフックURL（正規化した形） | する（送信に必要なため） |
| ウェブフック名・チャンネルID・連携日時 | する（画面表示のため） |

URL の後半（トークン）は投稿の鍵そのものなので、画面には ID までを表示して以降は伏せる。「記録をコピー」で書き出す内容からも同様に伏せる。

## 送る内容

科目名・時限・検知時刻・科目ページのリンクだけである。成績、課題、出欠数、氏名、学籍番号は送らない。送信は `background.js` の `postAttendanceWebhook("discord", ...)` が行い、宛先が `https://discord.com/api/webhooks/` で始まることと、ホスト権限があることを毎回確かめてから投稿する。

本文は `content` に入れ、`allowed_mentions: { parse: [] }` を付ける。科目名に `@everyone` のような字面が含まれていても、メンションとして鳴らさないためである。

## 解除

「連携を解除」を押すと、保存した送り先を消し、「Discordへ送る」を無効にし、`https://discord.com/*` の任意ホスト権限を返す。

**Discord 側のウェブフックは削除しない。** 削除は元に戻せず、同じ URL を使っているものが他にある可能性もあるため、消すかどうかは持ち主が決めることとした。完全に消す場合は、チャンネル設定の「連携サービス」から削除する。

## うまくいかない時

| 表示 | 原因 |
| --- | --- |
| ウェブフックURLは https://discord.com/api/webhooks/ で始まる形です | チャンネルのリンクを貼っている。「ウェブフックURLをコピー」で得られるものを貼る。 |
| この Webhook は Discord 側で削除されています | ウェブフックが消えている（コード 10015）。作り直して貼り直す。 |
| URLの後半（トークン）が違います | コピーが途中で切れている（コード 50027）。コピーし直す。 |
| 連携しましたが、テスト送信は届きませんでした | 送り先は生きているが投稿できていない。チャンネルの権限を確かめる。 |

スマートフォンに届かない場合は、Discord アプリでそのチャンネルの通知がミュートになっていないかを確かめる。

## 未検証の項目

- 実際の Discord ワークスペースでの往復は未確認である（試験では Discord 側を差し替えている）。
- 通知が集中した場合のレート制限（429 と `retry_after`）は扱っていない。1コマにつき1通しか送らないため現状では起きないが、送る場面が増える場合は再送の仕組みが要る。
