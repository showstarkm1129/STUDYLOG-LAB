# Studylog Bridge

ログイン済みのスタログから学習状況を**読み取り専用**で収集し、端末内のダッシュボードで確認する Chrome 拡張機能です。

Cookie、セッションID、認証トークン、プロフィール情報は取得・保存・出力しません。課題提出、出席登録、予定作成などの変更操作も行いません。

## ダッシュボードの機能

採用した次の11機能を収録しています。

1. 今日の科目だけの授業・課題・主要指標をまとめる「今日のブリーフ」
2. 同じ科目の連続時限を飛ばして表示する「次の科目」
3. 理由つきで表示する「次に確認する候補」
4. 手動完了を反映する「課題の整理率リング」
5. 75%基準の「出席アラート」
6. スタログ上の状態を確認する「未完了インボックス」
7. 科目別の「欠席セーフティ残量」
8. `− / ＋`とスライダーで操作する「欠席シミュレーター」
9. 出席・課題・授業回をまとめる「科目カルテ」
10. 不足データと影響先を示す「データ品質」

## スタログ画面内の場面別表示

右下の小さなカプセルを開くと、その場面で確認しやすい情報だけを表示します。詳細な分析は従来どおりダッシュボードへ分離しています。

- トップ: 今日中の次の科目、今日の授業、今日の科目の整理率、今日の科目にある未完了候補
- 時間割: 次の科目と今日の授業順
- マイページ: 課題の整理率とスタログ上の未完了
- 科目トップ: その科目の出席扱い率、欠席余裕、未整理項目
- 授業回: 現在の回を除外し、同じ科目にあるほかの授業回の未整理項目だけを一覧表示
- その他: 次の科目と全体の整理率

「今日のブリーフ」は今日の時間割にある科目だけを対象とし、チェック済み項目や欠席余裕は表示しません。データ品質は「データ管理」で確認できます。

授業回タイトルに「単位認定試験」と日付が明記され、その日付が時間割の日付と一致する場合だけ、次の科目・今日の授業・時間割カレンダーを「重要：単位認定試験」と強調します。日付のない試験名からは推測しません。

表示された未完了項目は、その場で手動完了にできます。チェック済み項目もパネル内に残り、同じチェックをもう一度押すと解除できます。保存状態はダッシュボードと共通です。

### クイズ回答の自動保存

- 通常のクイズ画面には、拡張機能のパネルやボタンを表示しません。
- 選択式の回答を変更すると短い待機後に、記述式は入力欄からカーソルを離して内容が確定した時に現在ページを保存します。
- 記述中のキー入力ごとには送信しません。カーソルを置いたままの場合だけ、30秒間入力がなければ保険として保存します。
- 連続した変更は1回にまとめ、保存中に回答が変わった場合は完了後にもう一度保存します。
- 保存には、検証済みの `plugin_quiz_student_page_view_accept` のXHRとフォーム確定を使います。画面移動や受験状態の中断は行いません。
- 解答値、通信本文、Cookie、認証トークン、レスポンス本文を拡張機能の保存領域へ記録しません。
- クイズ終了後に通常画面へ戻ると、通常の場面別表示とツールバーボタンを再び有効にします。

保存方式、実機で確認した内容、調査UIの再表示方法は [`docs/quiz-autosave.md`](docs/quiz-autosave.md) に記録しています。

## 課題ステータスと対応不要の類似表示

スタログでは、解答例や条件付き補講など、未完了表示でも対応不要な項目があります。そのため元の状態は変更せず、端末内に「手動完了」と「対応不要」を別レイヤーとして保存します。

- 課題は「完了（スタログ上で実際に完了）」「手動完了」「対応不要」を区別します。
- 「対応不要」は候補・未完了数・整理率の分母から除外し、専用一覧からいつでも解除できます。
- 同じ科目・同じ種別に類似した対応不要項目がある未完了課題は、状態を自動変更せず、表示優先度だけを下げて「対応不要の可能性」と表示します。
- 類似表示は保存済みの現在の項目からその都度計算し、将来の課題を自動的に対応不要へ変更する規則は作りません。
- スタログ上の状態は常に確認できます。
- 完了項目は「課題を実施して完了」と「手動で完了」を区別し、スタログの元の状態も併記します。
- チェックした項目は完了扱いとなり、課題一覧・整理率・候補へ一括反映されます。
- 「手動完了」一覧からいつでも解除できます。
- ダッシュボードの「課題の整理率」では、判定ルールと対象科目を確認できます。対象科目の選択は整理率だけに反映され、課題一覧・確認候補は変わりません。初期状態は全科目が対象です。
- 授業回ページの課題・クイズ等には、教材名の直後へ手動完了・対応不要の操作と類似ラベルを表示します。操作部は教材名の長さと画面幅に合わせて移動・折り返します。
- 科目カルテでも、存在感のあるチェックをもう一度押すだけで手動完了を解除できます。
- 場面別パネル、科目カルテ、データ管理のダイアログは、外側をクリックして閉じられます。
- ダッシュボードから書き出すJSONには手動完了情報も含まれます。

### ダイジェストと補講

同じ科目・同じ授業回にある `(D)` ダイジェストと `(H)` ダイジェスト補講を対として扱います。

- Dが未実施: 未完了にはDだけを表示し、HはDの実施後まで判定対象にしません。
- Dを実施して得点率が60%未満: 未実施のHを未完了として表示します。
- Dの得点率が60%以上: 未実施のHを「Dで補講完了」とみなし、未完了一覧と確認候補から除外します。
- 60%は達成扱いです。点数表記を取得できない場合は安全側に倒し、未実施のHを必要として扱います。

## 科目のアーカイブ

- 科目の実施期間の終了日までは通常表示します。
- 終了日の翌日0時からアーカイブ扱いになります。
- アーカイブ科目は、出席アラート、科目別セーフティ残量、欠席シミュレーター、科目カルテで通常は非表示です。
- 出席画面と科目画面の「アーカイブを表示」からいつでも確認できます。
- アーカイブ科目に未完了課題がある場合、その課題は課題一覧と確認候補へ引き続き表示します。
- 実施期間が取得できない科目は自動的にアーカイブしません。

## 出席の計算

- 全科目共通で、総授業数の75%を切り捨てた整数を最低出席数として扱います。
- 公欠は出席として扱います。
- 休講は出欠数・授業消化数が進まない前提です。
- 端数は生徒に有利になるよう、最低出席数では切り捨てます（欠席可能数では25%相当を切り上げます）。たとえば全30コマなら最低出席数は22コマ、欠席可能数は8コマです。
- 欠席余裕は、この欠席可能数から現在の欠席数を引いて計算します。
- シミュレーターは、指定した欠席以外の残り授業へすべて出席した場合の最終着地を表示します。

## 使い方

1. Chromeで `chrome://extensions` を開きます。
2. 「デベロッパーモード」をオンにします。
3. 「パッケージ化されていない拡張機能を読み込む」から、このリポジトリを指定します。
4. スタログへログインし、トップまたはマイページを開きます。
5. 右下の場面別カプセルを開き、**取得して保存** を押します。
6. トップ画面でも取得すると、日付・時限・教室・連続時限を保存できます。
7. Chromeの拡張機能アイコン、または場面別パネルの **ダッシュボード** を押します。

通常のスタログ画面では、データの変化頻度と取得負荷に応じて自動取得を分けます。

- 課題状態は、現在年度では30分ごと、未完了がある過去年度では1日ごと、完了済みの過去年度では30日ごとに確認します。
- 課題・レポートの送信を検知した場合とクイズ画面から戻った場合は、すぐに課題状態を確認し、さらに15秒後にも再確認します。連続した操作は1回にまとめます。
- 出席・科目状態は現在年度で3時間ごとに確認します。
- 科目の回一覧は現在年度で科目ごとに24時間を目安とし、1回の自動取得では1科目だけを順番に確認します。未完了がある過去年度は7日、完了済みの過去年度は30日を目安にします。
- カレンダー、科目、授業回を表示した場合は、追加通信を行わず、画面に表示された情報を随時保存します。
- 複数のスタログタブを開いていても、自動取得は同時に1タブだけが実行します。失敗時は5分以上空けて再試行します。

年度はスタログ側で現在表示されている選択を尊重し、拡張機能がバックグラウンドで勝手に切り替えることはありません。表示した年度のデータは年度別に保持され、以後その年度を表示したときに上記の頻度で確認します。クイズ画面そのものでは自動取得しません。

既に書き出したJSONは、ダッシュボードの **データ管理 → JSONを読み込む** から利用できます。

## 収集対象

- 履修科目: `classId`、科目名、期間、授業数、出席・欠席・公欠数
- 課題・テスト: 種別、名称、実施日、スタログ上の状態、科目／回へのリンク
- トップ時間割: 日付、時限、教室、連続時限、カレンダーリンクに明示された授業回ID
- 科目内の回: 授業日、画面に明示された課題・テスト・締切

教材の説明本文は保存しません。日時が取得できない項目について締切を推測しません。

## 保存方針

- 保存先は `chrome.storage.local` のみです。同期ストレージは使いません。
- JSONは明示的に書き出すまで外部へ送信されません。
- 課題・出席状況は個人情報として扱い、共有前に内容を確認してください。

## カスタムページ

ダッシュボードでは、ホーム・課題・出席・科目と同じナビゲーションに、名前と共通アイコンカタログから選んだアイコンを指定したページを複数追加できます。すべてのページは「ページを整理」から並べ替えられ、各タブ横の「★」でダッシュボードを開いた時に最初に表示するタブも選択できます。カード選択画面も同じアイコン体系を使用します。

追加したページには、カード選択画面から必要なカードを配置します。カードは12列のグリッドに並び、カードごとに許可された小・中・大のサイズだけを選択できます。カードは空白を残したまま任意のマスへ移動でき、自動的に左上へ詰め直されません。配置、ページ順、開始タブは他のダッシュボード設定と同じく `chrome.storage.local` に保存され、JSONの書き出し・読み込みにも含まれます。

新しいカードを実装する際の判断基準と登録方法は [docs/dashboard-card-authoring.md](docs/dashboard-card-authoring.md) を参照してください。

## 制約

- 出欠の収集値は `mySubjectStatus.php` を正とします。
- 「次の科目」は収集済みの日付範囲だけを使い、翌週の曜日などを推測しません。
- 回一覧は読み取り専用エンドポイントを優先し、バックグラウンドで科目ページを大量に開きません。
