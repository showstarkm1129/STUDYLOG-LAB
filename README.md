# Stalog Bridge + Lab

ログイン済みのスタログから、履修状況と課題・テスト状況を**読み取り専用**で収集し、端末内で活用する Chrome 拡張機能です。

このブランチには、収集データから何が作れるかを比較するための **Stalog Lab** を収録しています。大きな1機能ではなく、採否を個別に判断できる32個の小さな試作品を1つのダッシュボードにまとめています。

収集対象は次のとおりです。

- 履修科目: `classId`、科目名、期間、実施期間、授業数、出席・欠席・公欠数
- 課題・テスト: 種別、名称、実施日、状態、科目／回へのリンク
- 表示中のトップ時間割（日付・時限・教室・連続時限を正規化）
- 表示した科目内の回（ディレクトリ）・授業日と、画面に明示された課題・テスト・締切（教材の説明本文は保存しない）

Cookie、セッション ID、認証トークン、プロフィール情報は取得・保存・出力しません。課題提出、出席登録、予定作成などの変更操作も行いません。

## 使い方

1. Chrome で `chrome://extensions` を開く。
2. 右上の「デベロッパー モード」をオンにする。
3. 「パッケージ化されていない拡張機能を読み込む」を選び、このリポジトリのフォルダを指定する。
4. スタログにログインしてトップまたはマイページを開く。
5. トップまたはマイページで、右下の **スタログ収集** から **取得して保存** を押す。
6. **取得して保存** は、履修状況または課題一覧で見つかった全科目・講座の回一覧・授業日を、スタログが通常画面で使う読み取り専用 Ajax と科目トップ HTML から順に取得する。別タブやページ内 JavaScript は実行しないため、科目ページを開く必要はない。回内の教材・明示された締切も追加したいときだけ、通常どおりその科目ページを開いて同じ操作を行う。
7. トップ画面でもう一度 **取得して保存** を押すと、表示中の時間割を日付・時限・教室つきで保存する。
8. **JSONを書き出す** を押す。

Chrome のツールバーにある拡張機能アイコンを押すと **Stalog Lab** が開きます。スタログ画面右下の収集パネルから **Labを開く** を押すこともできます。

既に書き出したJSONで試す場合は、Lab左下の **データ管理 → JSONを読み込む** を使います。読み込んだデータも端末内の `chrome.storage.local` にだけ保存されます。

## Stalog Lab の試作品

- ホーム: 今日のブリーフ、次に切り替わる科目、次にやること、完了率、出席アラート、科目ヘルス
- やること: 未完了インボックス、優先度、固定、あとで見る、再挑戦候補、学習ルーレット
- 出席: 科目別の欠席余裕、基準切り替え、今後の欠席シミュレーター
- 成績: 異なる満点の正規化、得点分布、科目平均、弱点抽出
- 時間割: 週間表示、教室移動、空きコマ、ICS出力、今日の予定コピー
- 科目: 出席・課題・授業回・得点をまとめた科目カルテ
- 発見: 負荷ヒートマップ、授業タイムライン、自動インサイト、前回差分、集中タイマー
- 共通: 横断検索、ダークモード、未完了CSV、データ品質メーター
- レビュー: 各試作品の星を切り替え、採用候補だけをJSONで書き出し

出席余裕、優先度、科目ヘルス、自動インサイトは意思決定を補助する**試算**です。学校の正式な単位認定・出席判定ではありません。日時が取得できない項目について、締切を推測しません。

## 保存方針

- 保存先は `chrome.storage.local` のみです。同期ストレージは使いません。
- 課題・テストの状態などは個人情報として扱ってください。
- JSON は明示的に書き出すまで外部へ送信されません。共有する前に内容を確認してください。

## 制約

- 出欠の集計は `mySubjectStatus.php` を正とします。
- 回一覧・授業日は読み取り専用エンドポイントを優先し、回内の教材・締切はユーザーが開いた科目ページの本来の DOM から記録します。明示されていない日時は推測しません。バックグラウンドで科目ページを大量に開くことはしません。
- `・` など意味が未確定な出欠マークは、欠席として判定しません。
